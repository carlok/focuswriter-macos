# Decision: how to ship FocusWriter for macOS

*2026-11-18*

## Recommendation

Run a **separate packaging repository** (this one). It builds the unmodified
upstream tag and publishes ad-hoc-signed universal DMGs on its own Releases
page. Don't send patches upstream. Don't fork the source.

## Why not upstream first

The original plan was to send the deploy fix and CI upstream and become the
macOS packaging contact. Checked on 2026-11-18:

- `CONTRIBUTING.md` in gottcode/focuswriter bans contributions generated by
  LLMs "in all parts of the project". The repo also carries no-agents
  `AGENTS.md`/`CLAUDE.md` files.
- Pull requests and issues are disabled on the GitHub repository, so PR #213
  and its thread can't be read there.

These scripts were written with an AI assistant, so offering them upstream
would break the maintainer's stated policy. The GPL lets anyone build and
distribute binaries from the published source, and a downstream packaging repo
needs nothing from him.

## Why not a source fork

No macOS app-code bug turned up. Spell check uses Apple's NSSpellChecker,
ODT/DOCX/RTF support is compiled into the app, and SVG problems were purely
packaging. A fork would add rebase work and confuse users for no gain. If a
real macOS bug ever needs a code change, carry it as `patches/*.patch`
applied by `build.sh`, and keep it as small as possible.

## Root cause of the deploy failures (PR #213's problem)

Two separate issues, both in `macdeployqt`
(qtbase `src/tools/macdeployqt/shared/shared.cpp`, `deployPlugins()`, v6.12.0):

1. **SVG is dropped with any Qt.** macdeployqt copies
   `imageformats/libqsvg` only if the executable already links QtSvg.
   FocusWriter loads SVG backgrounds through `QImageReader` and never links
   QtSvg, so plain macdeployqt ships no SVG reader. The same happens with
   official Qt and with Homebrew Qt.
2. **Unresolved plugin dependencies, Homebrew only.** `iconengines` and
   `platforminputcontexts` are copied unconditionally from the plugin
   directory. Homebrew installs each Qt module in its own keg and merges
   their plugins into `/opt/homebrew/share/qt/plugins` with symlinks. The
   plugins come from qtsvg, qtvirtualkeyboard and qtpdf (qtwebengine), and
   the frameworks they need live in those other kegs, outside macdeployqt's
   search path. The result is "Cannot resolve rpath" errors and a bundle
   that only works on the build Mac.

**Fix (scripts/deploy.sh):** place `libqsvg.dylib` in the bundle first and
pass it to macdeployqt with `-executable=`. macdeployqt then copies QtSvg and
rewrites the plugin's install names like any other binary. With Homebrew Qt,
add `-libpath=$(brew --prefix)/lib` for issue 2. This was tested: both
builds pass the bundle audit. This repo uses official Qt via aqtinstall
instead, because Homebrew bottles are arm64-only and built for the host's
macOS version.

`scripts/audit.sh` fails the build if any binary in the bundle loads
something from outside the bundle, or lacks an arm64 or x86_64 slice.

## Verified on this Mac (macOS 27.0.1, arm64)

- Universal build of v1.9.1 against Qt 6.12.0, minimum macOS 14.4.
- Audit clean: all Mach-O files are universal and every dependency resolves
  inside the bundle.
- `codesign --verify --deep --strict`: valid on disk, satisfies its
  Designated Requirement.
- `spctl -a -vv -t exec`: **rejected** (expected for ad-hoc signatures;
  the quarantine flag doesn't change the result).
- The app starts native and under Rosetta with no plugin load errors.
- Image test inside the bundle: SVG, SVGZ and all eight theme JPEGs load on
  arm64 and x86_64. With `libqsvg` removed, the test fails as it should.
- The app's own theme preview renders an SVG theme background and all
  built-in themes.
- A simulated download (quarantined DMG, app copied out) is blocked.
  `xattr -dr com.apple.quarantine` then lets it launch.
- Still needs a person: the "Open Anyway" click-through, the spell-check
  underline, and ODT/DOCX/RTF rendering in the editor (see RUNBOOK step 5).

## Risks

- **Gatekeeper tightening.** If a future macOS removes "Open Anyway" for
  ad-hoc apps, the only fix is a paid Developer ID. Watch the macOS betas each
  June.
- **Runner images.** `macos-26` will be retired eventually; update the
  `runs-on` label when GitHub announces it.
- **Qt minimum OS.** Qt 6.12 needs macOS 14.4 or later. Users on 12–13 would
  need a Qt 6.8 LTS build; set `QT_VERSION=6.8.x` in `config.env` if that
  matters.
- **Mirror flakiness.** aqtinstall's mirror rotation served a bad TLS
  certificate once during setup; `build.sh` pins `download.qt.io`.
